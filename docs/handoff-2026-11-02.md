# Handoff: Toran, as of 2 November 2026

For any agent picking up this work. It covers what Toran is, what has been
built, the rules to follow, what's open, and how Milan (the founder) works
and what they bring.

## 1. The project in one paragraph

**Toran** is a UK website, "what's on at mandirs" (Hindu temples), that
helps families find events, festivals and seva (volunteering) at mandirs
near them. Mandir committees can look after their own page. It is run by
Milan and a co-founder, is pre-launch, and is in the pilot stage of
`docs/launch-plan.md` (Step 2: meeting committees, with a decision point in
the week of 14 December 2026).

- Supabase (Postgres with row-level security, Auth, Storage) in London.

- GitHub Actions for CI and an hourly uptime check.

Three languages: English, plus Gujarati and Hindi at `/gu` and `/hi`. Both
translations are drafts, waiting for a native speaker to check them.

## 3. Rules Milan has set (follow these)

- **Never send emails** to mandirs or anyone else. Drafts only; Milan sends.
- **Never paste keys or passwords** into chat. Milan types them into
  Vercel, Supabase or GitHub.
- **Never merge pull requests.** Milan merges.
- **One branch and one PR per piece of work**, off `main`, with green CI
  before handing over.
- **PR descriptions** have three sections: *What changes / Why / How it was
  checked*. They end with the Claude Code attribution lines.
- **No model names** in commits or PRs.
- **Subscribe to each PR** after opening it, and drive it to green.
- **If something already exists, trim it and say so.** Don't rebuild it.
- **18px minimum text**, WCAG 2.2 AA, and intuitive for every age group.
  Buttons must have words, not just icons.
- **Speed budget:** 250 KB JavaScript, 350 KB total per page (450 KB for
  pages with lots of data).
- **No personal details on public pages.**
- **Decision 0005:** no scraping of social media.
- **Decision 0006:** collect no personal data from the public until the
  company is registered with the ICO and the DPIA is signed off.
- The mandir contacts spreadsheet is private. **Never commit it.**
- Explain things in plain language. Milan is the decision-maker, not a
  developer. Recommend an option rather than listing every possibility.

## 6. Working notes for an agent

- **Database types:** `lib/database.types.ts` must exactly match Supabase's
  generated output (one line per table, columns alphabetical, no
  trigger-only functions). When it doesn't, CI's Database job prints the
  generated file.
- **Before pushing,** run tsc, lint, `prettier --check .` and
  `pnpm vitest run`. Then build and run Playwright:
  `PLAYWRIGHT_CHROMIUM_PATH=/opt/pw-browsers/chromium CI=1 npx playwright test`.
- **Database tests:** `tests/e2e-auth` runs in CI's "Login flow" job. To
  run it locally, use Docker plus `npx supabase@2.120.0 start -x realtime,imgproxy,postgres-meta,studio,edge-runtime,logflare,vector,supavisor`.
- **Hidden earlier page:** Next.js keeps the previous page in the page,
  hidden, after moving between pages. In tests, use `:visible` locators
  for header and menu elements.
- **Header layering:** the header has no backdrop blur. A blur would trap
  the full-screen menu inside the header.
- **Database migrations** reach the staging database on merge, and
  production only by running the Database workflow by hand.
